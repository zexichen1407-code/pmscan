# 复刻钱包 `0x4f1d5ae26fc31472966e951af3183308736d8de2` 的双边做市报价算法

> 一份**可直接编码**的双边挂单（maker quoting）算法。全程用交易白话，不涉及智能合约术语。
> 标的：二元体育市场（YES / NO 两条腿，合并成对后可换 $1）。
> 数据来源：网球单场逆向 + 669 个跨市场样本 + 价格对齐分析 + 对抗式复核（以复核修正后的数字为准）。

---

## 0. 一句话本质

他是一个**高频双边合并套利做市商**：同时在 YES 和 NO 两条腿上挂买单，让两条腿的报价之**和**钉在一个略低于 $1 的目标成本上（赚那几分钱的差），让左右两条腿的**分配**随比赛比分自由漂移；优先把**便宜的那条腿**（被低估的一侧）先吃满，等贵的那条腿价格掉下来、凑成对子时再合并换 $1，落袋差价。他**不靠对冲拉平库存**，反而**顺着便宜腿继续加仓**，把没配上对的那部分当成一个单独的方向性持仓扛着。

---

## 1. 报价规则（一段话讲清）

他对每条腿（YES、NO）各挂一个**买入限价单**，价格大约贴在该腿**当前实时盘口中价之下约 0.5–1.5 分**（不是挂在深处等便宜货——价格对齐显示他的成交价中位数只比实时中价低约 0.5–1.5 分，且零滞后，是"贴着盘口、被价格抬进去"的快速做市，不是埋伏远低位）。同时他给两条腿的报价**之和**设一个上限：**只在 YES买价 + NO买价 ≤ 目标成对成本 C 时才让一对成交**，C ≈ **0.965–0.98**（实测同时成交口径成对成本 0.964–0.968，跨 669 市场中位数 p+q = 0.983，即每凑成一对净赚 **约 1.7–3.6 分（中位 ~2 分，规模加权 ~3 分）**，注意：早先"5 分边际"是单场高水位的偏高估计，已被复核下修为 ~3 分）。两条腿之间怎么分由比赛走势决定：领先方涨、落后方跌（网球里 YES从 0.60→0.96、NO从 0.38→0.003），但两者之**和**被钉住（和的标准差 0.044，远小于单腿标准差 ~0.073）。重新报价非常快：**成交间隔中位约 12 秒**（跨市场约 44 秒），价格快速波动时（约 21% 的步是 >0.03 的大跳）他**继续留在盘口刷新报价**，而不是撤单躲开。下单量**两腿均匀，约 24–25 股/笔**，**不**在缺货那一侧加大单量。库存管理：**真正有统计支撑的行为是"顺势加便宜腿"**——他净多头偏向便宜的那条腿（网球里最后多扛了 +3193 股 NO/Cobolli），下一笔有 **~73% 概率继续加长已经更长的那条腿**（跨市场 Pearson +0.25），这是动量式单边吃便宜腿，**不是教科书式的回中对冲**。（单场里"缺货侧抬价、超仓侧压价"的微观回中规则，经置换检验 p=0.27/0.70 不显著，是价格趋势的假象，**应丢弃**。）攒够配对的 YES+NO 后定期**合并换 $1**（单场 89 次合并），把锁定的 (1 − p − q) 差价兑现；结尾允许净多便宜腿，让它自然结算。

**标定数字一览：**

| 参数 | 标定值 | 出处 |
|---|---|---|

| 每对目标净边际 (1−C) | **~2–3.5 分**（默认 3 分；硬顶 ~1.10 极少超） | 复核：中位 ~2 分、规模加权 ~3 分；p90 成对成本 1.025–1.031 |

| 库存倾斜方向 | **顺势加便宜腿**（不是回中） | Pearson +0.25，73% 继续加长腿 |
| 波动率调整 | **越波动、要求边际越宽**（平静 ~1% → 波动 ~3%） | 边际 vs 价格档数 Spearman +0.13 |

## 2. 报价循环伪代码

```text
# ============ 输入 ============
# mid_yes, mid_no      : 两条腿各自的实时盘口中价（来自 1 分钟/逐笔 CLOB 价格流）
# inv_yes, inv_no      : 当前已持有的 YES / NO 股数（成交累计，未合并的部分）
# matched = min(inv_yes, inv_no)   # 已经可以配对合并的对子数
# overhang_side, overhang_qty      # 没配上对的多头那一侧及其股数（方向性敞口）
# last_quote_time, last_trade_time
# time_to_resolution   : 距离市场结算/锁盘的估计时间（秒）

# ============ 可调旋钮（默认值见第 3 节）============
C_TARGET      = 0.97     # 目标成对成本上限（两腿买价之和不得超过它）
EDGE_FLOOR    = 0.015    # 单腿最起码要留的边际下限（防止贵腿追价）
PEG_OFFSET    = 0.008    # 贴盘口：买价比实时中价低多少（约 0.8 分）
CLIP          = 25       # 每笔下单股数
SKEW_GAIN     = 0.6      # 顺势加便宜腿的强度（>0 顺势，注意：不是回中）
MAX_OVERHANG  = 1500     # 单边未配对敞口上限（股）
REQUOTE_SEC   = 12       # 多久没成交/价格漂移多少就重报
DRIFT_TRIG    = 0.005    # 中价漂移超过它就立刻重报（0.5 分）
VOL_WIDEN_K   = 0.5      # 波动率每升一档，C 收紧多少
PULL_TTR_SEC  = 180      # 距结算少于它就开始收手
ADVERSE_JUMP  = 0.03     # 单步中价跳动超过它视为快速逆向，触发临时退避
PRICE_FLOOR   = 0.03     # 任一腿价格低于它（濒临归零）就停挂该腿
PRICE_CEIL    = 0.98     # 任一腿价格高于它（濒临到 1）就停挂该腿

# ============ 主循环（事件驱动：价格更新 / 成交回报 / 定时器 触发）============
def on_tick(mid_yes, mid_no, inv_yes, inv_no, ...):

    # ---- (A) 临近结算 / 极端价：收手 ----
    if time_to_resolution < PULL_TTR_SEC:
        cancel_all_quotes()
        # 只做合并，不再开新对子
        merge_matched(min(inv_yes, inv_no))
        return

    # ---- (B) 波动率自适应收紧目标成本 ----
    vol_level = recent_distinct_price_levels()      # 近窗口走过的不同价位数，越多越波动
    C = C_TARGET - VOL_WIDEN_K * 0.01 * vol_bucket(vol_level)   # 越波动，C 越低（要求更宽边际）

    # ---- (C) 快速逆向跳动：临时退避一拍，不撤全部 ----
    if abs(mid_yes - prev_mid_yes) > ADVERSE_JUMP or abs(mid_no - prev_mid_no) > ADVERSE_JUMP:
        widen = 0.01          # 多让出 1 分，等盘口稳定
    else:
        widen = 0.0

    # ---- (D) 基准两腿买价：贴在中价下方 ----
    bid_yes = mid_yes - PEG_OFFSET - widen
    bid_no  = mid_no  - PEG_OFFSET - widen

    # ---- (E) 钉住"两腿之和 ≤ C"：若超了，按比例下压（让 sum 回到 C）----
    if bid_yes + bid_no > C:
        excess = (bid_yes + bid_no) - C
        bid_yes -= excess * (mid_yes / (mid_yes + mid_no))   # 贵腿多让，便宜腿少让
        bid_no  -= excess * (mid_no  / (mid_yes + mid_no))

    # ---- (F) 库存倾斜：顺势加"便宜腿"（这是他真实的行为，不是回中）----
    cheap_side = "NO" if mid_no < mid_yes else "YES"
    # 把价格预算更多分给便宜腿，让它更容易成交、继续累积单边
    if cheap_side == "NO":
        bid_no  += SKEW_GAIN * EDGE_FLOOR
        bid_yes -= SKEW_GAIN * EDGE_FLOOR
    else:
        bid_yes += SKEW_GAIN * EDGE_FLOOR
        bid_no  -= SKEW_GAIN * EDGE_FLOOR
    # 重新夹回 sum ≤ C（倾斜只改分配，不改总额）
    if bid_yes + bid_no > C:
        d = (bid_yes + bid_no) - C
        bid_yes -= d/2; bid_no -= d/2

    # ---- (G) 贵腿纪律：贵的那条腿只在能凑出正边际时才挂 ----
    #     即"凑成对子后 1 - (bid_yes+bid_no) >= EDGE_FLOOR"才让贵腿吃单，否则把贵腿撤到很低/不挂
    expensive_side = "YES" if cheap_side == "NO" else "NO"
    if (1.0 - (bid_yes + bid_no)) < EDGE_FLOOR:
        # 边际不够：只挂便宜腿，贵腿暂不追（等它自己掉下来）
        if expensive_side == "YES": size_yes = 0
        else:                       size_no  = 0

    # ---- (H) 敞口上限：单边未配对持仓到顶就停止再加该腿 ----
    overhang_qty  = abs(inv_yes - inv_no)
    overhang_side = "YES" if inv_yes > inv_no else "NO"
    if overhang_qty >= MAX_OVERHANG:
        # 已扛太多便宜腿：停挂该（多头）腿，只挂对侧来配对
        if overhang_side == "YES": size_yes = 0
        else:                      size_no  = 0

    # ---- (I) 价格地板/天花板：濒临归零或到 1 的腿不挂（避免买进必输的腿）----
    size_yes = 0 if (mid_yes < PRICE_FLOOR or mid_yes > PRICE_CEIL) else CLIP
    size_no  = 0 if (mid_no  < PRICE_FLOOR or mid_no  > PRICE_CEIL) else CLIP
    # 注：两腿下单量保持一致（数据证实他不靠加大单量来补缺货侧）

    # ---- (J) 何时重报：定时 或 中价漂移超阈 ----
    need_requote = (now - last_quote_time > REQUOTE_SEC) \
                   or (abs(mid_yes - quoted_mid_yes) > DRIFT_TRIG) \
                   or (abs(mid_no  - quoted_mid_no ) > DRIFT_TRIG)
    if need_requote:
        replace_quote("YES", price=clamp01(bid_yes), size=size_yes)
        replace_quote("NO",  price=clamp01(bid_no),  size=size_no)
        last_quote_time = now

    # ---- (K) 合并已配对的对子，落袋差价 ----
    matched = min(inv_yes, inv_no)
    if matched >= MERGE_BATCH:           # 攒够一批再合并（省手续费/操作成本）
        merge_matched(matched)           # 把 matched 对 YES+NO 换成 matched 美元
        inv_yes -= matched; inv_no -= matched
```

```

**关键非显然规则（务必照做）：**
1. **不要为了拉平库存而对称双边报价**。先把便宜腿吃成单边大仓，贵腿只在它掉到能凑出正边际时机会性地补（步骤 G）。
2. **总额钉死、分配漂移**：永远先保证 `bid_yes + bid_no ≤ C`，库存倾斜只在这个预算内重新分配（步骤 E/F）。
3. **合并是兑现差价的唯一动作**：攒够配对就合并换 $1，剩下的单边敞口当方向性持仓单独管理。

## 3. 要调的旋钮 + 数据给出的起步值

| 旋钮 | 含义 | 起步值（来自数据） | 调参方向 |
|---|---|---|---|
| `C_TARGET` | 目标成对成本上限（两腿买价之和） | **0.97**（带 0.965–0.98 区间） | 上调 = 更激进、更多成交但边际薄；下调 = 更挑、成交少边际厚 |
| `EDGE_FLOOR` | 凑对后最起码留的边际 | **0.015（1.5 分）** | 贵腿追价纪律的硬线；嫌成交少就降，嫌亏损多就升 |
| `PEG_OFFSET` | 买价比实时中价低多少 | **0.008（0.8 分）** | 实测 0.5–1.5 分；调大=更被动更便宜但成交少 |
| `CLIP` | 每笔下单股数 | **25 股**（两腿一致） | 数据证实不按缺货侧加大；放大只为提高吞吐 |
| `SKEW_GAIN` | 顺势加便宜腿的强度 | **0.6**（>0 顺势，非回中） | 对应"73% 继续加长腿"；想更中性可降到 0，但那就偏离他的风格 |
| `MAX_OVERHANG` | 单边未配对敞口上限 | **~1500 股**（≈网球结尾 3193 的一半，保守起步） | 你能扛多少方向性风险就设多大；这是最大单笔亏损来源 |
| `REQUOTE_SEC` | 多久没动就重报 | **12 秒**（单场）/ 44 秒（跨市场） | 越小越贴盘口但操作成本/手续费越高 |
| `DRIFT_TRIG` | 中价漂移多少立刻重报 | **0.005（0.5 分）** | 配合 REQUOTE_SEC，价格一动就跟 |
| `VOL_WIDEN_K` | 波动越大、C 收得越紧 | **0.5**（平静要 ~1% 边际、波动要 ~3%） | 覆盖逆选择/腿差风险；波动市必开 |
| `MERGE_BATCH` | 攒多少对再合并 | **~150–200 对**（单场 89 次合并 15286 股 ≈ 170/次） | 越大省操作成本、占用资金越久 |
| `PULL_TTR_SEC` | 距结算多久开始收手 | **180 秒**（保守，按市场快慢调） | 临盘逆选择最毒，宁早勿晚 |
| `ADVERSE_JUMP` | 多大单步跳动算快速逆向 | **0.03**（对应 21% 大跳步） | 触发临时让宽一拍 |
| `PRICE_FLOOR / CEIL` | 濒临归零/到 1 的腿停挂 | **0.03 / 0.98** | 避免买进几乎必输的腿 |

## 4. 诚实的局限（必须读）

1. **我们只看到"成交"，看不到"挂单和撤单"。** 所有"买价比中价低 X 分""每 12 秒重报""波动时留在盘口不撤"都是从**成交价**反推的——而成交是他订单里被打中的那批，是有选择偏差的样本。我们看不到他挂了又撤、根本没成交的单子，所以**真实挂单频率、波动中是否撤单**都不可观测。"波动中坚守盘口"这条**无法被这份数据证伪**，照搬需谨慎。
2. **单场"库存微观回中"规则是假象，已剔除。** 原始报告里"缺货侧抬价、超仓侧压价"经置换检验不显著（NO p=0.27、YES p=0.70），实为"落后方价格趋势归零"的混淆。**真正有支撑的库存行为是跨市场的"顺势加便宜腿"**（Pearson +0.25，73% 继续加长腿）。编码时用第 2 节步骤 F 的顺势逻辑，**不要**写成回中。
3. **"5 分边际"是高水位，真实约 3 分且在压缩。** 同时成交口径只有 3.2–3.6 分，跨 669 市场中位仅 ~2 分、规模加权 ~3 分。**26.6% 的市场是负边际**（合并是在抢救已经腿差/买贵的仓位）。这门生意**边际极薄**：靠走量 + maker 返佣 + 资金高速周转赚钱，单笔几分钱，没有容错。
4. **maker 返佣是假设，且现在有 taker 费。** 数据里没有 maker/taker 标记，我们从"双边被动成交"模式推断他吃返佣——**无法证实**他没在某些腿上付 taker 费。而且 Polymarket 现已开征 taker 费，**净边际会被进一步吃掉**：你的 `EDGE_FLOOR` 必须把实际手续费加进去，否则名义有边际、实际净亏。
5. **残腿（未配对敞口）是最大风险。** 他刻意单边扛便宜腿，赌它最终结算为对自己有利。**这部分是纯方向性下注，不是套利**——便宜腿如果归零（站错队），那一仓直接亏光。`MAX_OVERHANG` 是你的命门，别设太大。
6. **边际在压缩。** 8.8% 的"规模加权肥尾边际"没能复现（复核得 ~3.2%），fat-tail 主要存在于高波动市，且竞争会持续把它磨平。复刻这套打法等于进入一个**已经很拥挤、边际逐月变薄**的赛道，要有"靠速度和量级、不靠单笔厚利"的预期。
